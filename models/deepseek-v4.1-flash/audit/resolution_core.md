# Core fidelity mapping resolution

Reviewed the entire pinned cards, A/B mappings, candidate lists, and review queue for the six repositories listed below. Only their resolved maps and supplemental candidates were written. No card bytes or verified data were edited.

All quantitative mappings use candidate IDs or exact source substrings. Supplemental candidates were extracted programmatically from source lines; `resolution_core_candidates.json` records the candidate ID, exact raw substring, line, pinned card SHA-256, and reason. Existing candidate IDs retain their original raw strings. The six pinned card hashes were independently checked against the index.

- **0xSero / Spark:** Retained separate v3.1 and legacy panel entries, each with its own dataset description. Full-vocabulary KL is against the native mixed FP8/BF16/MXFP4 checkpoint. Agreement fractions use `top1_fraction`. Total disk size includes the native part, EXL3 banks, and Engram; routed-expert bpw is explicitly a separate component rate. The original bpw candidate cited a component row that the row-label gate correctly refused to attribute directly to a panel name; the identical rate in the introduction is now source-extracted. Total checkpoint size was absent from the original candidates and is now source-extracted from the size row. The historical serving measurements and pending runtime acceptance do not establish a different quality panel.

- **sudoingx / EXL3 2.7:** Chose A's separation of position-weighted mean KL, equally weighted domain mean KL, and benchmark suites. The compound KL cell is retained as a candidate binding, then each entry receives its exact scalar via the validated prose mapping. This retains the card's own row label while preventing the domain mean from being read as an error interval. PPL and top-1 remain on the position-weighted panel. Native PPL and measured native suites remain cross entries. The two comparison packs were measured on this publisher's same panel/reference implementation and are not quotations. The J268 author/allocation is named but the exact source repository is not identified; its `of` is therefore `not named on card`. Download size explicitly excludes separately required official Engram shards. No total is synthesized by addition, and no per-token bitrate is substituted for storage bitrate.

- **diffbot / EXL3 3:** Kept the native repeat-run noise floor, NVIDIA NVFP4, current pack, and historical 2.0 pack as distinct measured entries. KL/top-1 remains per corpus; there is no invented aggregate. Corpus keys use `neutral_text`, `code`, and `agentic`, matching the actual table headers after separator normalization. B's earlier simpler stack and previous serving release are retained as separate historical measurements. Total disk download includes int4 Engram; expert bitrate is a component rate. - **drowzeys / TR3 Hybrid:** Retained native, TR3, and measured Pollard comparison. The reference is the native MXFP4-expert/FP8 release. Top-20 truncated KL is explicitly described in every entry's method and flag; it must remain separate from full-vocabulary measurements. Agreement uses `top1_fraction`. Own and native sizes are total disk values. The expert-weighted mix bitrate includes MXFP4 kept experts, rather than only the EXL3 tail. Objective scores remain correct-answer counts with the published denominator and contradictory heading identified in the metric label/flags. - **Lucebox / ROCMFP:** Retained all three own files plus the native teacher and antirez measured comparisons. Corpus-specific keys identify held-out fineweb-edu; the method explicitly says top-256 KL. - **jayleaton / EXL3 2.8:** Retained as-served and all-six-expert configurations separately, with distinct routing methodology. Native FP8/MXFP4 reference logits are restricted to top 2,048. Per-corpus KL remains eval mix, thinking spans, and wikitext-2. Fractional agreement uses `top1_fraction`. Same-engine Mia comparisons are measurements rather than quotations. Both quality configurations compare the same explicitly defined bpw-budget size subset for own and Mia, filed under `text_weights` with a precise subset flag (routed/shared experts, attention, CSA2, Engram projection). MMLU, reasoning questions, and tool-call results retain their published test descriptions and raw count/percentage forms. Runtime expert pruning is not represented as a modification of the stored base weights.

## Gate diagnosis and verification

Applied the six resolved maps to a scratch data root and ran the actual `verify.py` and `verify_columns.py` gates. Final result:

- 153 metric/size/bpw values verified against pinned lines; no presence, sign, or size-unit failures.
- 22 sizes checked for units beside their source numbers.
- 48 table-family bindings and 67 row-label bindings checked; no unexplained mismatches.
- Missing-repository inventory in this isolated run is expected: the scratch root deliberately contains only these six mapped repositories.

The original quarantines were not numerical errors. Spark's row-label problem came from applying a component-table bpw row to differently named quality panels. Diffbot's corpus columns contain a strict ordered `KL · top1%` pair whose metric names appear in the preceding caption rather than the headers. The source agent added narrowly constrained combined-cell parsing to the shared column gate; the resolved corpus keys exactly match that binding. It verifies slot order and does not generally waive family checks. The original source values remain unchanged.

## Remaining exclusions and chart requirements

No measured result for another model was imported (in particular the third-party GLM comparison and tiny invalid smoke test on the TR3 card). No speed, memory headroom, total download requirement during reassembly, theoretical format bitrate, or contextual percentage change was promoted to a fidelity measurement. No unavailable total checkpoint sizes were reconstructed.

Chart construction must retain corpus-qualified keys for diffbot, Lucebox, and jayleaton as distinct series; it must also retain panel methodology and size basis. A global alias from any of those keys to one aggregate KL would lose source meaning. The native noise floor and teacher rows remain references, not quantization candidates. `top1_fraction` needs canonical chart support while keeping its original raw fraction.
