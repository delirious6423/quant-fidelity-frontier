Scope: the six repositories in `work/deepseek-v4.1-flash/resolve_5.json`. Both independent mappings were compared with each pinned source card and candidate list. Only this wave's resolved maps, resolved candidate supplements, and this audit note were written. Source snapshots and the independent mappings remain unchanged.

All numeric claims use existing candidate IDs, exact pinned-source substrings copied programmatically, or supplemental candidates beginning at `c9001` with their source lines. Supplemental raw strings were checked against the pinned source bytes. No values were typed into the production verified dataset.

Validation was performed by applying the six resolved maps through `qcl_map.apply` into an isolated temporary data root with only these repositories and their pinned snapshots. The real verified directory was not changed. Queue mapcheck passed. The verbatim/sign/unit gate passed with no failures, and the column gate reported no metric/header mismatches. The row-label gate retains three source-binding false positives: the two vcruz position-window entries carry the same artifact's expert size from the main quality row, and the REAP-272E repository-only size is labeled only “this repo.” The application adapter derives explicit row labels from metric candidates but currently omits size candidate labels. Those size candidates have the correct source labels and all values, columns, and units pass. Propagating the size candidate label through the existing adapter is sufficient; no source exception or number change is needed.
